pycognition: A Dual-Process Cognitive Architecture Integrating Deterministic Procedural Execution and Deliberative LLM Synthesis

Oleh Riabtsev
Referat Forschung, Nachwuchsförderung und Transfer (RFNT), Universität Vechta, Germany
ORCID: 0009-0003-7848-6418 | Software License: LGPL-3.0-or-later
Abstract

This paper introduces pycognition, an open-source neurosymbolic framework formalizing dual-process cognitive dynamics for autonomous software agents. Contemporary agent frameworks uniformly route deterministic and repetitive sub-tasks through stochastic foundation model APIs, incurring substantial latency, financial overhead, and execution drift. pycognition addresses this efficiency gap via a segregated execution topology: an ultra-fast procedural tier (System 1) executing validated Python scripts, and a deliberative tier (System 2) orchestrating frontier LLM inference. The Skill Crystallization pipeline compiles verified reasoning traces into strongly typed modules, verified via Abstract Syntax Tree (AST) safety inspection and sandboxed unit testing via pytest. An empirical trial across 100 heterogeneous workloads confirmed a rigorous three-tier performance model. Operating akin to an adaptive JIT compiler, the architecture explicitly accounts for script development latency (mean 7,192.20 ms). The per-skill break-even point is reached at 4 invocations (ideal) and 5 invocations (accounting for the 36.2% sandbox rejection overhead), followed by an asymptotic speedup of 11,326.7x. System-wide, algorithmic response time decreased by 44.7% (155.46 s vs. 281.13 s), while cumulative token expenditure dropped immediately by 38.0%, scaling to 71.4% procedural coverage in the final quartile.

Keywords: Cognitive Architectures, Autonomous Agents, Dual-Process Theory, Program Synthesis, AST Validation, Amortized Inference, JIT Compilation, Break-Even Point, pycognition.

1. Introduction

The deployment of LLM agents across enterprise environments has exposed a fundamental inefficiency between natural language generative flexibility and deterministic algorithmic execution. Standard paradigms (ReAct [6], Plan-and-Solve [9], AutoGen [10]) utilize stochastic autoregressive inference as an all-purpose runtime. Algorithmic transformations, log parsing, and numerical calculations are repeatedly offloaded to cloud model APIs alongside strategic planning, incurring linear and quadratic token costs, round-trip latencies of up to 5,000 ms, and non-deterministic regressions.

Dual-Process Theory [1], [2] resolves this trade-off: System 1 governs rapid procedural routines, while System 2 allocates intensive deliberation to novel domains. The pycognition framework transfers this principle to software agents as an adaptive JIT compiler: encountering new task classes, the agent invests System 2 resources into synthesizing deterministic Python modules, verifies their safety, and registers them into procedural memory.

2. Background and Related Work

The partition between declarative representations and procedural rules has historical foundations in ACT-R [3] and Soar [4]. Amortized inference [15] established the validity of replacing costly iterative search with cached evaluation operators. Foundation models (Codex [12], DeepSeek-Coder [13]) and agents like Voyager [11] demonstrated skill accumulation, but lacked deterministic AST sanitization, automated unit test generation [14], and rigorous multi-tier break-even modeling.

3. Proposed Methodology and Architecture

An incoming computational task T=⟨id,p,x,μ⟩ is arbitrated via MetaArbiter maximizing expected utility U(a∣T) based on vector similarity γ(T,Σ) with threshold θ=0.55. The crystallization operator Ψ synthesizes verified subroutines guarded by ASTSecurityValidator and an isolated subprocess pytest sandbox (t=15 s).

4. Implementation and Empirical Evaluation

4.1. Three-Tier Latency and Break-Even Modeling (N = 100)

  • Tier 1. Marginal Latency and Asymptotic Acceleration: A compiled System 1 routine executes in L―S1=0.292 ms. A baseline algorithmic LLM call averages Lbase=3 307.41 ms. The marginal speedup is 11,326.7x (19,103.9x across all System 2 calls).

    Effective speedup progression: S(1)=0.31×; S(2)=0.63×; S(4)=1.26× (break-even reached); S(10)=3.15×; S(50)=15.73×; S(100)=31.41×.
  • Tier 3. Workload-Level Progression across 100 Tasks:
    Baseline uncompiled LLM time: 471.66 s (281.13 s algorithmic). In pycognition, asynchronous task response time dropped to 155.46 s (1.81x speedup, -44.7% execution time). Synchronous wall-clock time including 47 crystallization cycles (338.03 s) totaled 493.49 s on algorithmic tasks. In Quartile 4, synchronous wall-clock speedup reached 0.96x (2.84x execution speedup), with full workload break-even horizon converging at N*≈207 tasks.

5. Discussion and Limitations

Filtering 36.2% of candidate subroutines prevented silent regressions caused by degrees-of-freedom mismatches in variance (6 z-score cases), boundary flaws in IPv4 parsing (4 cases), and floating-point rounding errors. Explicitly accounting for synthesis latency (7.19 s) provides an honest engineering baseline, indicating that compilation should operate as an asynchronous background task. Lexical TF matching exhibited synonym fragmentation and cross-lingual dilution, establishing the requirement for dense multilingual embeddings.

6. Conclusion and Future Work

pycognition demonstrates the empirical viability of JIT compilation for cognitive agents. Synthesis investments amortize within 4–5 task repetitions, achieving an 11,326.7x marginal speedup, a 44.7% execution time reduction, and immediate 38.0% token savings. Future work focuses on self-healing reflection loops and dense embedding deduplication.
